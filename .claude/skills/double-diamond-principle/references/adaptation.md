# 適用條件、例外與跨專案用法

用於選擇流程深度、處理限制，或判斷是否應回返前一個問題。依 Design Council 對非線性與迭代的說明調整；以下決策表與示例是本 skill 的實務整理。

## 適用條件與調整

| 情境 | 處理方式 |
| --- | --- |
| 挑戰模糊，只有「需要做某個功能」 | 先確認是既定範圍還是可討論假設，連回希望改善的結果；不要擅自推翻使用者指定產品 |
| 問題已驗證、研究仍適用 | 承接 Define 的成果，進入方案或驗證工作；只補影響當前決策的缺口 |
| 使用者只要某階段的成果 | 完成本次交付，把必要的上游假設簡短標明；不硬擴充成完整工作坊 |
| 解法明確的小修正 | 直接處理並驗證；雙鑽石可用來釐清一個疑點，不必重新做需求研究 |
| 時間／預算很小 | 縮小問題與本輪決策，利用已有證據和低成本原型；保留尚未驗證的限制 |
| 無法接觸使用者 | 可做桌面分析、現有資料綜合、假設清單與測試材料；不能宣稱完成共創或使用者驗證 |
| 只有利害關係人偏好 | 保留其決策權與現實限制，同時區分它和使用者證據；視任務比較選項或在既定範圍內設計 |
| 緊急服務／系統故障 | 先依任務範圍恢復必要能力，再針對成因與長期改善做探索；不要求先跑完四階段 |
| 原型測試發現問題定義錯誤 | 依新證據回到 Define，必要時補 Discover；不是每次測試失敗都要全部重來 |
| 各方案都未達需要 | 可捨棄、延後、重新界定或停止；Deliver 不保證一定推出一個產品 |
| 多角色、多組織的系統性挑戰 | 視需要加入關係、依賴與長期影響分析；不要把單一介面優化等同整個系統改變 |

非線性依據：[Framework for Innovation](https://www.designcouncil.org.uk/resources/framework-for-innovation/)。系統性挑戰的延伸見 [Systemic Design Framework](https://www.designcouncil.org.uk/resources/systemic-design-framework/)；其 Explore、Reframe、Create、Catalyse 與額外原則屬延伸框架，不能無聲替換本 skill 的四階段。

## 何時發散、何時收斂

- **問題證據不足**：擴大對人、情境與原因的理解，而不是先產生大量解法。
- **問題有根據但解法過早單一化**：發展不同機制的候選，找出最影響取捨的未知。
- **資訊足以支持下一個低成本、可逆決策**：收斂並試做，不等待所有問題都完全確定。
- **決策影響較大或難以回復**：提高對關鍵假設的驗證要求，但只補與該影響有關的證據。
- **結果與原假設衝突**：說明哪項假設失效，回到相應層次；不要用繼續 polish 迴避反證。

上述是依兩次發散／收斂及迭代原理作出的操作判準，並非固定 stage gate 或需要逐階段批准的流程。

## 跨專案示例（假設案例，不是研究結果）

### 服務流程：圖書館場地預約未到場

若目前只有未到場紀錄和館員說法，先整理時間、群體、規則及資料缺口，不能立即斷定讀者需要新 app。可先形成待驗證的問題 brief，再比較提醒方式、取消流程或預約規則等不同作用機制。用紙本流程或小範圍試行檢查最重要的假設，觀察讀者及館員的負擔；依結果擴大、修改或回返問題。

### 已有原型：企業內部報銷流程

若問題與成功判準已由本專案確認，直接檢視候選原型的任務完成、錯誤與受助情況。辨識哪些數據能比較、哪些情境尚未涵蓋，選定需要的改進或追加測試；不為了畫出完整雙鑽石重做所有訪談。完成原型不等於已改善實際報銷週期，仍要在交付後追蹤結果。

這兩個示例說明同一方法可服務不同領域與不同起點，不規定專案必須使用其方案、工具或指標。

## 常見誤用

| 誤用 | 修正 |
| --- | --- |
| 把四階段當作一次性的順序交接 | 依學習回返，讓探索、原型與測試互相影響 |
| 把 Develop 等同寫程式 | 發展與比較方案，原型精度依要回答的問題決定 |
| 把 Deliver 等同 deploy | 小規模測試、改進與捨棄同樣屬於交付；發布依任務範圍 |
| 用生成的 persona 充當訪談證據 | 標明假想角色，將其主張轉成待驗證問題 |
| 工作坊投票最高就稱為使用者需要 | 保留共識與偏好，但用適當證據驗證人的需要與方案效果 |
| 四個階段各佔一樣多時間 | 按不確定性、可用證據與決策影響分配投入 |
| 為了發散而重新開放已固定的限制 | 沿用使用者範圍；只在有新證據時明示衝突 |
| 套入官方指南的固定樣本數 | 依研究目的、差異與結論用途設計樣本；數字範例不是保證 |
| 只服務最容易被找來的人 | 說明沒被涵蓋的人及潛在排除，設計合適的參與方式 |

原理及適用性見 [The Double Diamond](https://www.designcouncil.org.uk/resources/the-double-diamond/) 與 [官方歷史的 Working with the process](https://www.designcouncil.org.uk/resources/the-double-diamond/history-of-the-double-diamond/)；具體防誤用做法屬本 skill 的操作設計。
